# 发布与回归门禁手册

> 基于 [release-regression-gatekeeper](../README.md) skill 的标准模板。本文档定义
> CAP_Agent 项目从冒烟回归到发布、回滚的端到端门禁规则。

## 1. 版本类型与回归模型

| 版本类型 | 典型场景 | 回归层级 | 轮次 | 通过标准 |
| --- | --- | --- | --- | --- |
| 日常迭代 | 功能优化、P2/P3 修复 | smoke + core + 受影响模块 | 1 轮 | 核心用例 100% 通过；无遗留 P0/P1 |
| 紧急修复 Hotfix | 线上 P0/P1、紧急需求 | smoke + 修复点 + 最小影响范围 | 1 轮（可压缩） | 修复点通过；核心流程无阻塞 |
| 大版本/重构 | 新功能、架构升级 | smoke + core + full + 兼容性/性能 | ≥ 2 轮（修复后 + 上线前） | 用例执行率 100%；无 P0/P1；Agent 全维度阈值通过 |

### Agent 项目分层

- **冒烟回归**：约 10-30 条，验证核心意图、基本回答、工具调用和多轮关键信息
- **核心功能回归**：覆盖 P0/P1、输出 Schema、常见用户问题；自动化优先
- **全量回归**：覆盖所有用例、工具、意图、边界、异常；自动化 + 人工并行

### 通用项目分层

- **冒烟**：首页/登录、核心业务、关键 API
- **核心功能**：P0/P1、核心增删改查接口
- **全量**：功能、兼容性、边界、异常、多浏览器

## 2. 回归范围确定流程

1. **需求影响分析**：从需求、验收标准、发布说明确认改动对象
2. **代码/配置差异分析**：检查提交文件、配置、Prompt、模型、工具定义、知识库变更
3. **接口依赖分析**：追踪上下游接口、数据表、消息、第三方服务、缓存
4. **历史缺陷分析**：查找易错模块、线上逃逸、重复失败案例
5. **用户场景分析**：优先高频路径、核心业务、资金/权限/安全路径
6. **分层选择**：标记为 smoke/core/full，给出排除项和补偿措施
7. **确认准入**：开发自测、环境、数据、账号、上轮阻塞全部满足

## 3. 发布方式选择

| 版本/风险 | 推荐方式 | 放量原则 |
| --- | --- | --- |
| 低风险日常迭代 | 全量 | 风险较高时先验证 10% 流量 |
| 高风险/大版本/Agent 核心变更 | 灰度 → 逐步 → 全量 | Agent 采用 1% → 5% → 20% → 50% → 100% |
| 线上 P0/P1 故障 | 紧急发布 | 优先恢复服务，保留回滚，24 小时内复盘 |

## 4. 发布门禁

### 发布前

- [ ] 开发提交版本包、发布清单、变更说明、影响范围、风险点
- [ ] 测试准出达成，回归结果和缺陷清单归档
- [ ] 配置、Prompt、模型参数、工具定义、知识库版本固化（Agent）
- [ ] 预发布环境完成最终冒烟
- [ ] 灰度规则 / 白名单准备
- [ ] 回滚包 + 回滚配置 + 操作步骤 + 负责人确认
- [ ] 测试、产品、项目负责人、运维审批完成
- [ ] 发布群 + 值守安排明确

### 发布中

- 按全量 / 灰度 / 紧急流程执行
- 灰度每阶段记录流量比例、样本量、错误率、延迟、用户反馈、日志、告警
- 只有测试/运维确认通过才进入下一阶段；指标异常立即停止放量
- 核心业务高峰期（09:00-19:00）原则上不发布；无值守能力时延期

### 异常升级

- P0 故障：5 分钟内响应
- P1 故障或核心体验受损：10 分钟内上报，立即停止放量
- 其他异常：在发布群通报，记录时间、影响、处置人、后续动作

### 发布后 30 分钟内（Agent 专项）

- [ ] 基础连通性健康检查返回正常且非空
- [ ] 执行 5-10 个核心 Prompt，成功率 ≥ 90%
- [ ] P95 响应延迟 ≤ 基线 1.5 倍
- [ ] 工具调用成功率 ≥ 95%
- [ ] 输出符合约定 Schema，错误率无显著上升
- [ ] 监控无新增 P0/P1 告警

### 发布后 30 分钟内（Web/API 通用）

- [ ] 首页 + 核心页面可用，无 5xx
- [ ] 登录、下单、支付等核心流程成功
- [ ] 核心 API 返回 200 且数据正确
- [ ] 监控无新增 P0/P1 告警
- [ ] 数据库变更时检查数据正确、无死锁或慢查询

## 5. Agent 灰度实施表

| 阶段 | 比例 | 验证重点 | 观察时长 | 回滚条件 |
| --- | --- | --- | --- | --- |
| 1 | 1% | 核心意图 + 工具调用 | 30 分钟 | 错误率 > 1% 或 P0 |
| 2 | 5% | 响应延迟 + 输出格式 | 1 小时 | 错误率 > 0.5% |
| 3 | 20% | 多轮对话 + 复杂任务 | 2 小时 | 负面反馈变差 |
| 4 | 50% | 全量功能 | 4 小时 | P1 故障 |
| 5 | 100% | 最终验证 | - | - |

## 6. 紧急发布（Hotfix）

1. 开发负责人、测试负责人、产品确认必须走 Hotfix
2. 开发在修复分支完成修改，提交自测结果、影响范围、回滚方案
3. 测试执行最小化回归：修复点 + 冒烟 + 故障相关功能
4. 项目负责人完成线上审批，运维按紧急发布流程部署
5. 测试与产品验证故障是否解决，监控观察至少 30 分钟
6. 发布后 24 小时内完成复盘，补充回归用例，防止问题再次逃逸

## 7. 回滚规则

### 触发条件（满足任一）

- P0 线上故障、核心功能不可用、服务崩溃
- Agent 无响应、意图识别大面积失败、工具调用大面积异常或安全绕过
- 错误率突增、监控大量告警、数据异常或业务安全受影响
- 灰度指标超过该阶段阈值，且规定观察窗口内无法恢复

### 执行步骤

1. 立即停止发布/放量，通报异常等级和影响范围
2. 切换上一个稳定版本或稳定配置
3. 测试执行冒烟，确认核心流程恢复
4. 线上监控观察 30 分钟
5. 完成原因分析、修复、回归和重新发布评估
6. 24 小时内复盘，将逃逸问题补入用例库和监控

## 8. 发布申请与结论

```markdown
# [项目/版本] 发布与回归结论

- 版本类型：日常迭代 / Hotfix / 大版本重构
- 变更摘要：…
- 影响模块/接口/Prompt/模型/工具：…
- 风险等级与发布方式：全量 / 灰度 / 紧急

## 回归结果
- 回归层级：smoke / core / full
- 用例版本与执行轮次：…
- 总数/通过/失败/阻塞/执行率：…
- 修复点回归：…
- P0/P1 遗留：…

## 发布门禁
- 测试准出：通过 / 不通过
- 产品验收：通过 / 不通过
- 回滚包与方案：已确认 / 未确认
- 预发布冒烟：通过 / 不通过
- 值守与监控：已安排 / 未安排

## 结论
- 发布建议：Go / Conditional Go / No-Go
- 灰度阶段/当前比例：…
- 停止放量或回滚条件：…
- 责任人和下一步：…
```
