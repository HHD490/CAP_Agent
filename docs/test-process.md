# 测试流程治理手册

> 基于 [test-process-governor](../README.md) skill 的标准模板。本文档定义 CAP_Agent
> 项目从需求评审到上线验证的端到端质量控制链路。

## 1. 阶段与门禁

| 阶段 | 输入 | 关键动作 | 输出 | 门禁 |
| --- | --- | --- | --- | --- |
| 需求评审 | 需求文档 / 原型 | 识别风险、歧义、不可测点、依赖 | 评审纪要 + 风险清单 | 重大歧义已关闭或登记 |
| 测试设计 | 评审纪要 | 编写覆盖正常/异常/边界/兼容性/规则的用例 | 用例集 + 评审记录 | 三方评审通过 |
| 开发提测 | 编码 + 自测 | 自测报告 + 变更说明 | 提测包 | 准入检查通过 |
| 冒烟测试 | 提测包 | 验证启动、登录、核心业务 | 冒烟结论 | 通过才能系统测试 |
| 系统测试 | 冒烟通过的包 | 全量执行 + 缺陷管理 + 回归 | 测试报告 | P0/P1 100% 修复并回归 |
| 验收 | 系统测试通过 | 产品/业务确认 | 验收结论 | 通过 |
| 上线 | 验收通过 | 灰度放量 + 线上验证 + 值守 | 发布记录 | 30 分钟内监控稳定 |
| 复盘 | 线上数据 | 逃逸问题回流 | 复盘报告 | 24 小时内完成 |

## 2. 准入与准出清单

### 准入（冒烟前必须满足）

- [ ] 需求已评审，重大歧义已关闭
- [ ] 开发自测通过，无阻塞性 P0/P1
- [ ] 测试环境、`.env`、数据、账号、权限就绪
- [ ] 版本包可用，服务和关键接口可调用
- [ ] 范围、用例、优先级和执行计划已确认

### 准出（上线前必须满足）

- [ ] 用例执行率 100%，阻塞项有结论
- [ ] P0/P1 缺陷 100% 修复并回归通过
- [ ] 缺陷影响范围已回归，无关联功能被破坏
- [ ] 产品验收通过，测试报告已评审
- [ ] 遗留 P2/P3/P4 有责任人、风险说明、目标版本
- [ ] 上线风险评估完成，无不可接受风险
- [ ] 回滚包 + 灰度规则 + 值守人员已就位

## 3. Agent 项目专项

PoC 涉及 5 个 Agent 模式，必须先完成确定性功能测试，再进入离线评测。

### 阶段衔接顺序

1. `test-scope-case-designer` 界定范围 + 风险
2. `test-tool-governor` 确认工具 + 环境 + 权限
3. **本流程（test-process-governor）治理阶段 + 门禁**
4. `agent-nondeterministic-evaluator` 离线评测 + 基线对比
5. `release-regression-gatekeeper` 决定发布方式

### 离线评测准出（额外要求）

- [ ] 核心回归集通过率 ≥ 阈值（见 `core-regression.json`）
- [ ] 与基线相比核心指标恶化 ≤ 10%
- [ ] 安全/对抗/核心计算 100% 通过
- [ ] 人工抽检 ≥ 10% 复杂语义用例
- [ ] 测试集、原始输出、报告、失败明细归档

## 4. 缺陷分级

| 等级 | 定义 | 示例 | 发布影响 |
| --- | --- | --- | --- |
| P0 Blocker | 核心流程不可用 / 安全风险 | Agent 无法启动、数据丢失、安全绕过 | 必须修复 + 回归 |
| P1 Critical | 主要功能异常，无规避方案 | reply 误判 explicit、accepted 被 stale | 本轮修复 |
| P2 Major | 非核心异常，有规避方案 | 边缘流程异常、提示错误 | 后续版本跟踪 |
| P3 Minor | 轻微问题 | 拼写、对齐 | 优化队列 |
| P4 Trivial | 建议类 | 文案润色 | 按产品优先级 |

## 5. 暂停条件

出现以下任一情况立即暂停 + 升级：

- 冒烟失败率 > 30%
- 核心流程存在 P0
- 环境不稳定导致无法执行
- 出现无规避方案的 P0
- 版本频繁变更且未通知测试

## 6. 角色职责

| 阶段 | 测试 | 开发 | 产品 | 运维 |
| --- | --- | --- | --- | --- |
| 需求 | 识别风险、写用例 | 评估可行性 | 解释需求 | 评估环境 |
| 提测 | 跟踪、检查材料 | 编码 + 自测 | 确认范围 | 准备环境 |
| 测试 | 准入、冒烟、系统、回归 | 修复缺陷 | 验收 | 排障 |
| 发布 | 验收、值守 | 配合部署 | 确认内容 | 部署、监控、回滚 |

## 7. 报告与归档

- **缺陷报告**：`docs/defects/<version>/<id>.md`，使用 test-process-governor skill 模板
- **测试报告**：`docs/reports/<version>/report.md`，含范围、执行结果、缺陷、结论
- **Agent 评测报告**：`docs/agent-evaluation/<date>.md`，由 `scripts/agent-eval-report.mjs` 生成
- **基线归档**：`tests/agent-evaluation/baselines/<version>.json`（接入真实模型后启用）

## 8. 复盘节奏

- 每次上线后 24 小时内
- 每月一次质量例会
- 每版本一次流程 review
