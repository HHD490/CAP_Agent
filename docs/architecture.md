# PoC 架构与领域边界

## 核心实体

- Customer：公司级客户主档，统一承接主动和被动来源。
- Contact：客户联系人，拥有独立的可联系、待核验、无效、退订与禁止联系状态。
- Product：PMS Product 级销售产品；核心快照只读，获客营销资料可编辑。
- MatchResult：公司 × 产品的 Agent 匹配候选，保留客户与产品版本。
- Opportunity：客户 × 产品 × 来源的获客机会；进度、负责人、待办和阻塞都属于机会。
- AgentTask：五种 Agent 任务的生命周期、业务 Trace 和结构化结果。
- EmailDraft：机会下的中英文邮件版本；人工审核并发送。
- Inquiry：虚拟官网询价及当次产品推荐快照。

## Agent 写入原则

1. 原始来源数据只追加，不由 Agent 修改。
2. AI 画像保存在推断层；人工确认后才进入标准化事实层。
3. 匹配结果是建议，人工接受后才创建主动获客机会。
4. 官网留资是被动获客的唯一特殊入口：留资后自动创建机会并运行画像/匹配。
5. Agent 不自动发送邮件、不自动分配负责人、不自动执行不可逆关闭操作。
6. 运行失败不推进业务阶段。

## 任务状态

`queued → running/thinking → generating → executing → completed`

失败进入 `failed`，人工停止进入 `stopped`。同一目标的同一种任务运行期间不允许重复创建。页面每 1.5 秒同步任务状态，完成或失败时推送通知并局部刷新数据。
