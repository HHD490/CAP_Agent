# 链航智能获客中台 PoC

面向跨境物流业务的主动 + 被动获客内部演示系统。新项目从零构建，旧版 `logistics-outreach-poc` 保留为只读参考。

## 本地启动

要求 Node.js 22 或更高版本。项目使用 npm，不要求安装 pnpm。

```bash
cd /Users/neo/Work/FDE/CAP/logistics-acquisition-poc
npm install
npm run dev -- --host 127.0.0.1 --port 3100
```

- 虚拟官网：http://127.0.0.1:3100/
- 运营后台：http://127.0.0.1:3100/admin

若本项目没有 `.env`，本地开发会临时复用相邻旧 PoC 的 `.env` 模型与邮件配置；创建本项目自己的 `.env` 后自动停止复用。不要提交真实密钥。

## PoC 能力

- 统一客户库：30 条虚构 WCA 风格客户、3 条官网客户，支持模拟同步、CSV/Excel 导入和手工录入。
- 统一产品库：4 个 PMS 原型产品 + 8 个明确标注的模拟产品。
- Acquisition Agent：客户画像、产品匹配、建联内容、回复判断、交接摘要五种真实模型任务。
- 统一机会进度：9 个业务阶段；Agent 的请求、思考、生成、执行是任务状态，不占业务阶段。
- 人机协作：Agent 建议、人工确认、人工执行；建联工作台以聊天方式呈现邮件线程，PoC 预置多语言往来且不要求真实发送。
- 版本管理：客户或产品更新后保留旧匹配并标记过期，已接受机会只提示复核、不被自动覆盖。
- 演示时钟：可推进 3 天，展示 3/7 天跟进提醒和无回复暂停。

## 推荐演示顺序

1. 打开运营后台“获客总览”，介绍统一客户、产品、匹配、机会与 Agent 任务。
2. 在“数据接入”运行一次模拟 WCA 同步，再到“客户库”查看新增档案并运行画像 Agent。
3. 在“智能匹配”查看证据、风险、缺失信息和过期提示，接受一条匹配并选择联系人。
4. 在“获客机会”观察建联 Agent 自动启动、进度条更新和中文草稿生成。
5. 在“智能匹配”点击“查看建联邮箱”，进入聊天式邮件线程，切换英文、德语、日语、西班牙语会话，查看原文、AI 中文参考和意向判断。
6. 在阶段 6/7 的机会中模拟一封具体询价回复，观察 Agent 判断为明确意向并推进到待分配。
7. 分配“负责人 A”，观察 Agent 生成交接摘要并进入第 9 阶段。
8. 返回虚拟官网提交询价并留资，展示被动获客如何进入同一客户库；默认 `test@example.com` 会演示主动/被动来源合并。
9. 修改官网询价后重新匹配，观察立即运行提示、旧匹配过期和后台自动更新。
10. 在总览推进演示时间，查看跟进提醒；最后点击“重置演示”恢复初始数据。

## 明确边界

- 不登录或抓取真实 WCA 目录；“WCA 同步”只生成虚构演示记录。
- 不包含正式 CRM 销售漏斗、合同、订单、支付、权限与审计平台。
- 不模拟新触发的 AI 结果：模型失败会保留失败状态并允许重试。
- 不保存或展示模型隐藏思维链，只保留结构化证据、结果与工具执行记录。
